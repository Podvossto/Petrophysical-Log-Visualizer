# Petrophysical Log Visualizer — PROJECT.md

A Windows desktop tool that loads LAS well-log files, cleans the data so it is ready for interpretation, and plots one log per well. Built for the PetroRes Software Engineering Intern take-home: a petrophysicist points it at a folder and gets a cleaned dataset, a report of every change, and a plot per well.

## Scope
### IN — what this project does
- **Load** every LAS file in a folder into an in-memory model of wells and their curves; a bad file never crashes the program; report what could not be read and why
- **Condition**: missing values, depth order and sampling, units, different curve names for the same measurement — with a report of what changed in each file
- **Plot** each well: depth on the vertical axis increasing downward; tracks GR · resistivity (log scale) · bulk density + neutron porosity on one track; a well missing a curve still plots what it has
- Save plots as PNG **and** browse wells in a window
- Deliverables: git repo with full history, README (build/run, design, conditioning decisions, limitations, AI usage), plots for all wells + conditioning report
### OUT — what it does NOT do (deliberate decisions)
- Horizontal zoom / pan, crossover shading, caliper / DRHO / PEF tracks
- Resampling to a regular depth step, interpolating gaps, statistical normalisation (values stay in physical units)
- Environmental corrections, depth matching between runs, splicing runs
- Full LAS 3.0 support (read best-effort: the log data section only)

## Features (= requirements — one row per feature + AC; tag MUST/LATER)
| ID | Tag | Feature | Passes when (AC) |

| F6 | MUST | Conditioning report | `conditioning-report.csv` one row per change + `summary.md` |
| F7 | MUST | Log plot PNG | One PNG per loadable well, 3 tracks, fixed standard scales, missing track says "No … curve" |

## User Flow
- Petrophysicist → opens the app → **Open folder** → sees every well with Loaded / Partial / Failed → clicks a well → sees the log + what was changed → **Export all** → PNGs + reports in `output/`
- Headless: `PetrophysicalLogVisualizer.App.exe --batch <inFolder> <outFolder>` → same outputs, no window (used to generate deliverables and to measure)

## Runtime pipeline
| Step | Job | Watch out for |
|---|---|---|
| 1. File Discovery | Find the LAS files to process | Duplicate files, unreadable files, folder boundaries |
| 2. LAS Parsing | Read the header, curve definitions and data values | Several LAS versions, WRAP=YES, NULL values, malformed data |
| 3. Validation & Inspection | Check that what was read is sound | Row count, depth order, step, missing curves |
| 4. Data Conditioning | Apply the conditioning rules | Keep the meaning of the original data; record every change |
| 5. Data Model | Store each well and its curves in the form the system uses | Depth and curves must stay correctly aligned |
| 6. Plot Rendering | Turn the data into a multi-track plot | Scales, depth axis, missing values, performance |
| 7. Conditioning Report | Summarise the problems found and the changes made | Every entry must be traceable back to the data |
| 8. Export | Save plots and reports to files | File names, output location, output requirements |

Each stage takes the previous stage's output only; Core never touches UI.

## Techstack / Architecture
| Layer | What | Why |
|---|---|---|
| Language / Runtime | C#, .NET Framework 4.8 | Named first in the brief; already in every Windows 10/11 — reviewer installs nothing |
| UI | WinForms (standard controls) | The UI is thin (list + plot + details); designer-friendly, easy to explain |
| Plotting | ScottPlot 4.1 (`ScottPlot.WinForms`) | Allowed by the brief; Signal/SignalXY plots handle hundreds of thousands of points; one renderer for window and PNG |
| Data model | depth `double[]` + one `float[]` per curve | No per-row objects; small heap, GC never scans the arrays; float is enough for log readings, depth keeps double precision |
| Rules | `CurveRules.cs` (role → mnemonics + accepted units + conversion) | One readable table; adding an alias is a one-line change + a test |
| Tests | xUnit | Standard, one dependency, test project only |
| Projects | `PetrophysicalLogVisualizer.Core` (reader, conditioning, model, reports) · `PetrophysicalLogVisualizer.App` (WinForms + plotting + `--batch`) · `PetrophysicalLogVisualizer.Tests` | Core has no dependency on UI → reusable for batch/server later |
| Environment constraints | Any CPU, Prefer 32-bit **off**; DPI aware | 32-bit caps memory at ~2 GB |
